## Documentation rules

1. Keep public project documentation in English so it can serve as portfolio documentation and a shared reference for future contributors.
2. Keep personal learning notes separate from this directory. Personal notes may be written in Persian.
3. Update these documents when an architectural decision changes; do not document speculative technology as if it were already implemented.
4. Use Architecture Decision Records (ADRs) for decisions that are important, difficult to reverse, or likely to be questioned later.
5. Label planned features as planned. Do not describe future clients, integrations, or infrastructure as implemented until they exist and are tested.
